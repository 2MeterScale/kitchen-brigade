# 厨房の組み方

仕事ごとに新しい役を立てると、毎回同じ事を調べ直し、勘どころが消え、役どうしが仕事を壊す。持ち場を決め、同じ持ち場の仕事は同じ役へ。勘どころは持ち場の帳面に溜める。持ち場は固定しない（増やし、割り、合わせ、畳む）。どの種類のプロジェクトにも使う。

**読み方。** 書いてある事は、使い捨てで困った経験への手当てで、理由が本体。数は目安。形が仕事の邪魔なら崩してよい。小さな仕事に名簿や定義を作らない。

## 役の型

| 型 | 数 | する事 | 勘どころ |
|---|---|---|---|
| シェフ | 本人と Claude | 目的から何を作るか決める。出来を自分の目で見る。渡す前にプランを済ませる | 会話と覚え書き |
| スーシェフ | 一人 | 持ち場の仕事を一つにまとめ、直後に確かめる。通しの確かめ、見せる物の作り直し、片づけ | 溜める |
| 持ち場の料理人 | 持ち場ごと一人 | その持ち場の物を作る、直す | 溜める |
| 助っ人 | 一時 | 期間限定の専門。終わるとき関わる帳面へ渡す | 渡して終わり |
| 手伝い | その都度 | 探す、数える、読むだけ。安いモデルで | 溜めない |
| 外の目 | その都度、**必ず新しい役** | 何も知らずに見る（盲検、審査） | **溜めさせない** |

小さなプロジェクトはスーシェフを置かず、シェフが兼ねる。持ち場が二つ以上で、まとめで事故が出たら置く。

## 置く物（ひな型は `templates/`）

| 物 | 場所 | 中身 |
|---|---|---|
| 名簿 | `.claude/brigade.md` | 持ち場、受け持ち、状態、候補、組み替えの履歴 |
| 共通の決まり | `.claude/kitchen.md` | 先頭に「Start here」六行。目的、正本、作業の場所、環境の仕掛け、確かめ、仕事の終わり。**七キロ以下**（全員が毎回読む。経緯と長い説明は `kitchen` 持ち場の札へ） |
| 定義と帳面 | `.claude/agents/<名>.md` と `.claude/agent-memory/<名>/` | 定義は短く（受け持ち、境、道具の一行）。帳面は下の形 |

定義の見出し: `name`、`description`（「この種の仕事はいつもこの役へ」）、`model`、`memory: project`、書きかえる持ち場には `isolation: worktree`。共通の事を定義に写さず、「Start here を読む」と指すだけ。

## 帳面 = 索引 + 札 + 引く道具（全部読み返さない）

役は始まりで帳面と決まりを全部読み、毎ターン読み返す。大きい帳面は、何もしないうちに文脈を食う。だから形を変える。

- `MEMORY.md` は**索引だけ**（一行一札、最大 60 行、新しい順）。`notes/*.md` は一話題一ファイル（frontmatter: title, date, tags, status current|superseded、本文）。`[[slug]]` でつなぎ、フォルダは Obsidian でそのまま開ける。
- 引く道具は `scripts/`（Python 標準ライブラリだけ。ネットも導入も要らない）。
  - `notes.py recall "<語>" [--role r] [-k 5]` 順位付けして小さく出す（日本語は二文字の組＋識別子の完全一致、古い札は下げる）
  - `notes.py show <slug> [--lines a-b]` / `notes.py add <role> --title … --tags … [--supersedes <slug>] < 本文` / `notes.py split <role|--all>`（古い形の長い `MEMORY.md` を札にする。何度走らせてもよく、一行も失わず、失えば止まる）/ `notes.py stats`
  - `codemap.py find|outline|where`（Swift。他の言語は `DECL` の正規表現を足す）: 宣言の場所と行の範囲を出し、ファイルを丸ごと読ませない。`.claude/cache/` を `.gitignore` に。
- **入れ方**: `scripts/` の四つ（`notes.py notesplit.py textrank.py codemap.py`）を `Tools/kitchen/` に写し、名簿や決まりの中の道のりを合わせる。既存の長い帳面は `python3 Tools/kitchen/notes.py split --all`。
- 役の規則: 索引だけ読む。聞く前、調べ直す前に `recall`。コードは `find/outline/where` してから、行の範囲だけ Read。仕事の終わりに `notes.py add`（`MEMORY.md` に手で足さない）。古い札は `--supersedes`。決まりではなく、何が起きて、なぜを書く。経過は書かない。
- 役の勘どころを、本人の決定より上に置かない。決定が変わったらシェフが札を直す。

## 役どうしのやり取りを安くする

- 役の費用の大半は、指示ではなく**ターン数**（毎ターン全文脈を読み直す）、残る道具の出力、地の文。
- **報告はファイルへ**（`/tmp/<project>/reports/<job>.md`）。返すのは五行: できたか、ブランチと先頭、試験の一行、最大の発見、報告の道。送り直さない。途中で止まって起こさない。
- **役どうしの指示と報告は英語**で短く。本人の言葉、画面の文言、ファイル名は原文のまま。帳面は本人が読む言語。
- 役の中でも英語で、ツール呼び出しの間は一行まで。大きな少ないターン（独立した呼び出しは一度に）、道具の出力は小さく（ログはファイルへ、末尾か grep）、読み直さない、絵は一枚の並べ絵に、待つなら前で待つ。
- **決まった作業は台本（スクリプト）で。役を立てない**（アップロード、一覧取得、整形）。シェフは人参を切らない: 切るだけの仕事は一番軽い手へ「その通りに」、原因不明の物だけ強い手へ調べる所から。

## 始め方

1. これまでの仕事を物で束ねる（無ければ層、章、工程から）。束が持ち場の候補。
2. 受け持つ**物**で切る（仕事の種類で切ると同じ物を二つの役が触る）。少なく始める。迷う所は候補として名簿へ。
3. ひな型を写して埋める。毎回調べ直していた事を決まりへ。
4. 帳面を空で始めない。報告とシェフの知識から札を先に作る。
5. 名簿に日付と「組んだ」。

## 仕事の渡し方

1. 名簿で持ち場を見る。無い、二つにまたがるなら先に組み替え。
2. シェフが正本の該当箇所を先に読む。指示は目的、正本の場所、任せる範囲、触らない所（やり方の細部は帳面と役の判断へ）。
3. 同じ会話にその持ち場の役がいれば、新しく立てず SendMessage で続ける。
4. 走る役への足し込みは、**中身で**決める。向きが同じで言い直し、量、項目、土台の変化の連絡なら足してよい。何を作るか、何のためかが変わる、前の知らせと食い違う、同じ間違いを繰り返すなら、止めて渡し直す。知らせは一通、置きかえる所を書く。
5. 戻ったらまとめ役へ。直後に確かめる。出来の判断はシェフが自分の目で。「できた」をそのまま本人に渡さない。

## 組み替え

区切りごとにシェフが名簿を見直す（本人に伺わずに決めてよい）。履歴に日付、何を、なぜ。

| しるし | する事 |
|---|---|
| どこにも当てはまらない仕事が繰り返す | 持ち場を足す（一度きりは助っ人） |
| 二つが同じ物を触り合い、まとめでぶつかる | 切り直す |
| 一つの帳面が別々の話題で膨らむ | 割る（札を話題で分ける） |
| しばらく来ない | 休みにする（帳面は残す） |
| 物が無くなった | 畳む（生きている札を引き継ぐ持ち場へ移す） |
| 期間限定の専門 | 助っ人 |
| 役が古い思いこみで濁る | 同じ持ち場の新しい役に替える（札から消してから） |

割る、合わせる、畳むときは、**帳面を先に動かす**。

## Claude Code の注意

- `isolation: worktree` は既定ブランチから切られる。決まりに「最初に指示のコミットまで進める」。
- 定義を足しても、少し経つまで選べない。その間は汎用の役に定義と帳面を読ませる。
- 役の記憶は会話をまたがない。残るのは札だけ。
- 別々のブランチで札を足すと、合流のあとに `MEMORY.md` がぶつかる。解いたあと `notes.py split --all` で足された節を札へ畳む。

## やらない事

外の目に帳面や前の仕事を教えない。手伝いに判断を渡さない。持ち場の役に他の持ち場を「ついでに」頼まない。持ち場を先回りして細かく切らない。
